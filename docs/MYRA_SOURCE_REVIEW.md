The separately reviewed `codeninjavik/MYRA-AI-ASSISTANT-` repository's tracked files are its README, `LICENSE`, `.gitignore`, and images; it contains no Python/Flutter application source, setup script, dependency manifest, implementation files, or MYRA settings export. ## Advertised capabilities vs this Android project

The target already has native equivalents for provider/chat routing, Gemini and other provider configuration, local/offline Gemma experimentation, speech input and system TTS, notes/memory, reviewed app-launch and reminder actions, selected-file preview, web research, and scoped Google tools. Some are experiments or require their own provider/OS setup; their presence does not establish parity with MYRA's README claims.

The README's Windows window/keyboard/mouse/clipboard control, broad app automation, screen reading, and desktop file operations cannot be ported as-is to Android. They require different Android APIs and explicit, feature-specific OS consent. The app intentionally has no hidden always-on microphone, unrestricted accessibility control, arbitrary file access, or automatic messaging. A dedicated offline voice and an autonomous, no-review website-generation agent are not implemented as equivalents. The optional Gemini website drafter described below is online and review-gated, not a port of upstream implementation.

## Current source-backed Files queue pass

The MYRA Android Files matrix describes a temporary queue of up to 25 unique user-selected audio files, with row-to-play, seeking, previous/next, pause and stop; it is local-only and is discarded when Files closes. Personal AI's existing single-file local audio preview is extended with this bounded queue in `MYRA_AUDIO_QUEUE.md` and `MYRA_AUDIO_PREVIEW.md`. The adapter skips duplicate paths and picker items without a local path, and keeps the app's existing pause-on-background behavior rather than claiming an exact match for MYRA's background-stop semantics. New unit tests cover queue construction and bounds but could not be run locally because Flutter is unavailable. Android picker/codec/runtime behavior and Redmi testing remain unverified until CI/device checks complete.

## Later verified source-backed Android handoffs

The public Android project also has a separate, explicit System Clock timer handoff based on the available MYRA Android snapshot's `ClockTimerData.kt`: the user enters 1–86,400 whole seconds and an optional label up to 40 characters, then taps to open Android's `ACTION_SET_TIMER` screen. Android Clock remains visible and the user starts the timer there; this app does not schedule or run a background timer, issue a notification, or claim the timer has started. Invalid input is rejected at both the Flutter and Android boundaries, and a missing Clock handler is reported as unavailable. The existing foreground-only Pomodoro timer is unchanged. Focused Dart parser/widget tests and Kotlin parser tests cover bounds, malformed input and labels; Android intent dispatch and real-device Clock behavior still require device validation.

The MYRA transfer remains partial, not full feature parity. The available snapshot contains native Android sources but not the original desktop/PyQt application source or the owner's MYRA settings. Android/UI/device behavior, external service/API access, and settings parity are unverified where the feature matrix says so; desktop-only automation and integrations cannot be inferred from README claims. Continue using `myra-ultra/FEATURE_MATRIX.md` as the detailed source-vs-Android capability ledger and mark each slice by its actual implementation and tests, not as a blanket parity claim.
