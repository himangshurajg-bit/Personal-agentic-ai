# MYRA source review and Android adaptation

Reviewed upstream repository: <https://github.com/codeninjavik/MYRA-AI-ASSISTANT-> at commit `4f8cd94385274dde8b8eea02834b93ae08471b5e` (23 October 2026).

## The public desktop repository is not the Android source

The separately reviewed `codeninjavik/MYRA-AI-ASSISTANT-` repository's tracked files are its README, `LICENSE`, `.gitignore`, and images; it contains no Python/Flutter application source, setup script, dependency manifest, implementation files, or MYRA settings export. Its README describes a Windows 10/11 Python assistant, but these files do not contain the advertised implementation. The separate installation guide also describes installation rather than providing the Android project. Neither repository is the source tree used for this transfer.

## Actual MYRA Ultra Android source found locally

The owner-controlled checkout at `https://github.com/himangshurajg-bit/MYRA-Ultra-Android.git` is available at commit `f5af95528ee955c17a573fe574662da419108b3d`. It contains the native Kotlin/Jetpack Compose app under `native-android/`, the preserved WebView/Chaquopy prototype under `prototype/`, feature and architecture matrices, tests, and the MYRA portrait asset. Its own README calls the native app an incremental port, not feature-complete; `FEATURE_MATRIX.md` records implemented slices and remaining Android/runtime gaps. The source notice says the original desktop/PyQt tree is excluded, so it is not part of the available source bundle. The current source checkout has a pre-existing local edit to `prototype/gradlew.bat`; it was preserved.

`SOURCE-NOTICE.md` states that the source owner permits reuse for this private Android work, while warning against public distribution without separate permission. This transfer remains private and local; the MYRA source is included as a separate reference/source bundle, not copied wholesale into the Personal Agentic AI app. Its assets are not silently repurposed in the target app.

The separate MYRA Android source checkout has a `SOURCE-NOTICE.md` permitting private development reuse but not public redistribution. ## Advertised capabilities vs this Android project

The target already has native equivalents for provider/chat routing, Gemini and other provider configuration, local/offline Gemma experimentation, speech input and system TTS, notes/memory, reviewed app-launch and reminder actions, selected-file preview, web research, and scoped Google tools. Some are experiments or require their own provider/OS setup; their presence does not establish parity with MYRA's README claims.

The README's Windows window/keyboard/mouse/clipboard control, broad app automation, screen reading, and desktop file operations cannot be ported as-is to Android. They require different Android APIs and explicit, feature-specific OS consent. The app intentionally has no hidden always-on microphone, unrestricted accessibility control, arbitrary file access, or automatic messaging. A dedicated offline voice and an autonomous, no-review website-generation agent are not implemented as equivalents. The optional Gemini website drafter described below is online and review-gated, not a port of upstream implementation.

## Personal Agentic AI transfer branch

The target checkout is `personal-ai-transfer-final` on local branch `wabi/myra-transfer-continued`, based on `757312e`. Its existing staged, unstaged and untracked changes were preserved. The transfer work already present covers local task CSV import/export and sorting/editing; water, habit and expense logging with Home summaries; text conversion tools; Web Projects source editing and task lists; on-demand read-only System Monitor; focus timer; selected PDF/video/DOCX/image and camera paths; and reviewed local workflow-step edits. Those are partial feature mappings, not complete MYRA parity.

The target also has pre-existing provider/chat configuration, secure credential storage, app memory, voice and many Android handoffs. MYRA's feature matrix includes a broader set of native Chat/Live Voice tools, system handoffs, task reminders, Files/Media/Settings/backup behavior and WebForge. Some concepts overlap with existing target functions, but identical behavior, settings, safety gates and Android runtime behavior have not been established for every row. Windows-only automation cannot be copied as-is to Android; Android permissions and current safe handoffs remain feature-specific. No claim of full parity is made.

Local transfer additions include selected local media support (PDF page navigation and video seeking; bounded DOCX paragraph/table extraction; on-device PDF OCR; Latin-script image OCR; user-launched camera), editable workflow steps, Base64/form-URL/JSON conversion, local HTML/CSS/JavaScript drafts and an optional review-gated Gemini website drafter, a read-only system monitor, a focus/break timer, a private local journal, and a manual restore flow for Personal AI's own locally exported JSON backup. Journal entries support create, view, edit and delete with a chosen date and text, using the app's existing on-device storage; no network, sync or AI submission is involved. Backup restore validates the supported schema before writing, previews category counts, and requires confirmation before replacing records. Provider credentials, OAuth tokens, security settings and other app preferences are kept outside the restore; there is no sample or real personal backup data. These additions are Personal AI-side implementations; the separate MYRA source tree and its assets are not part of the target code. The additions do not claim full feature parity.

## Verification and delivery

On 27 October 2026 the complete Flutter analyzer returned “No issues found,” and the full `flutter test` command exited successfully. The local Rust search crate passed formatting, all 7 unit tests and Clippy. The target app's Android JVM suite passed all 22 tests. The broader Gradle `testDebugUnitTest` task is not wholly green: two upstream `local_auth_android` test-fixture initializations fail because their configured `maxSdkVersion` is 35 while this app targets API 36; the app module tests pass. A fresh debug APK built successfully for Android `arm64-v8a` and `x86_64`; inspection confirmed both `libpersonal_local_search.so` libraries are inside the APK. `adb devices -l` listed no connected device, so no install/run on Android or Redmi hardware is verified.

The owner asked for the project source/files/assets and a debug APK. A private MYRA source bundle was created from the available 179-file Android checkout, including its source matrices, tests and both portrait asset paths; its ZIP integrity and required contents were verified. A separate Personal Agentic AI source archive snapshots the current local branch's tracked and non-ignored untracked project source, tests, documentation and assets. Both archives omit Git metadata, generated build/cache outputs, machine-local configuration, credentials, signing keys and user-data databases; the debug APK is a separate file. The source archives and debug APK remain local/private artifacts and are not committed into the target repository. Their existence does not imply a release or a phone installation.

## Remaining settings and parity gaps

The MYRA source includes settings code and backup schema, but no owner-specific settings export or saved values are present in the source checkout. The backup format can contain a name, language, optional daily water target and selected local records; it excludes provider API keys. The native Settings screen also has a model choice and barge-in toggle. To transfer personal values accurately, the only needed input is a redacted settings screenshot or exact non-secret values for profile name, reply language, chosen Gemini model, barge-in setting and optional water target. Do not send an API key, password, token or recovery secret in chat; enter any needed API key only in Personal AI's secure settings. Existing Personal AI settings and data remain untouched.

## Remaining parity gaps identified from the available MYRA matrix

This comparison is against the available MYRA Ultra Android increment, not the absent original desktop/PyQt implementation. The target has useful counterparts, but matching names do not establish equivalent behavior:

- Personal Agentic AI already has its own chat/provider and voice paths, task records, browser/web research, local Android handoffs, selected-file/document/media support, workflows/MCP integrations, and a separate settings store. Those records/settings were preserved, not replaced with an imported MYRA backup.
- The target's local task CSV import/export, filtering/sorting and editing do not yet establish parity with MYRA's due-date and user-enabled WorkManager reminder behavior. Its provider/voice features are not verified against MYRA's duplex Gemini Live session, quick-command chips, or constrained latest-turn tool/review policies.
- Android utility actions in MYRA's matrix—including explicit flashlight/torch, Wi-Fi panel, clipboard, vibration, SMS/WhatsApp composer, stream volume, per-window brightness, location sharing, and notifications—need a per-action Personal Agentic AI mapping and runtime review. Some target handoffs overlap, but this pass does not certify all of those as equivalent or add blanket device control.
- The target's local Web Projects editor, nested files, basic static review, explicit `@file` context preview, user-selected ZIP export and confirmation-gated Gemini draft are partial WebForge counterparts. There is no equivalent executable local preview; generated JavaScript remains unexecuted by design. MYRA-specific project backup/restore and project-management details are not fully ported. Separately, Settings can now restore a validated Personal AI JSON export after showing its supported category counts and explicit replacement confirmation.
- The target has an on-demand read-only system monitor, focus timer, water/habit/expense tools, and document/image/OCR/media operations. The journal slice is implemented as date-and-text entry create/view/edit/delete stored locally, with a Journal tab in Assistant tools; it is not synced or sent to AI. Personal AI's own JSON export can now be restored locally after schema validation and preview; this is not an importer for MYRA-specific backups or settings. MYRA-specific metrics, reminder behavior, and file/camera lifecycle details still need feature-by-feature comparison; no hardware behavior was tested here.
- MYRA's desktop/PC-control concepts and Termux commands are not directly compatible with a standalone Android app and are not ported as unrestricted shell, accessibility, or remote-computer control.
- Personal MYRA setting values remain unavailable. Needed non-secret values: preferred name, reply language, selected Gemini model, barge-in on/off, and optional daily water target. Do not send any API key, token, password, or recovery secret in chat; any API key belongs only in Personal AI's secure settings.
