# MYRA live-download adaptation

The MYRA Android source exposes a `download_file` live tool for one exact HTTP(S) URL in a direct spoken download request. It checks the current utterance against the URL proposed by the model, rejects unsafe/unsupported URL arguments, and shows the full URL and filename for approval before starting Android Download Manager. The source cautions that network data may incur charges and that enqueueing is not proof the file completed.

Personal AI now has a narrow client-side adaptation for the existing Live Conversation flow. It recognizes only a complete transcript of `download <HTTP(S) URL>`, optionally prefixed by `please` or containing `this file`; it validates with the same `DownloadInput` used by the Downloads screen, then reuses that screen's final review before calling the existing Android download channel. The transcript is not sent to the chat model when it matches. Free-form requests, inferred URLs and Gemini function-call routing are not implemented; this is not full MYRA live-tool parity. The Android review and user confirmation remain required, and the app reports only Android's enqueue receipt, not download completion.

The feature derives from `myra-ultra/native-android/app/src/main/java/com/myra/ultra/nativeapp/GeminiDownloadPolicy.kt`, `GeminiLiveSession.kt`, and `MainActivity.kt`, with policy tests in `GeminiDownloadPolicyTest.kt`. Personal AI's `mobile/lib/download_input.dart` and Android `enqueue_user_download` channel validate the target and start the app-specific download. Full Android 16 CI and Flutter tests are the verification gates; actual live-transcription, Android-dialog, Download Manager and Redmi-device behavior still need device testing.
