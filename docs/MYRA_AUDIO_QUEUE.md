# MYRA local audio queue adaptation

MYRA's Android Files feature matrix describes a temporary audio queue built only from audio the user selects in Android's document picker: up to 25 unique tracks, row tap to play, seek/previous/next/pause/stop controls, no upload or file modification, and queue cleanup when leaving Files. The source record is `myra-ultra/FEATURE_MATRIX.md`; this is a behavior-level adaptation and does not copy MYRA source code or assets.

Personal Agentic AI's existing Files audio card now accepts multiple user-selected audio files and builds an in-memory queue from at most 25 unique entries that expose a local path. Missing paths and duplicate paths are skipped. Tapping a queue row starts that track; the controls support previous/next, play/pause, stop, seek, and elapsed/duration display. Selecting a new batch replaces the previous queue. The queue is not persisted, exposed to Gemini, uploaded, or used for background playback. Leaving Files disposes the player and drops the queue. The existing lifecycle pause behavior is retained when the app leaves the resumed state.

The adapter reuses the existing `file_picker` multi-file result and `just_audio` playlist APIs. New unit tests cover the queue's 25-track bound, stable picker order, duplicate and missing-path handling, fallback filenames, and existing time labels; they could not be run locally because Flutter is unavailable on the build computer. These are code-level tests, not proof of Android document-provider grants, codec support, playback controls, or lifecycle behavior on a device. Android 16 CI and a Redmi device test remain necessary; the picker can return entries that do not provide a usable local path, which are skipped with an in-app notice/error.
