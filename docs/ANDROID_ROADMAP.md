# Android assistant roadmap and capability ledger

Primary target: Android16/API36. Current phone-only priority means no computer is required for local functions; it does not forbid optional internet. The user selected both offline and online inference, and independent offline/online recognition. Repository/package identity stays Personal-agentic-ai. The assistant display name is editable; HIRAKI is not a hardcoded identity requirement.

This ledger captures the full undertaking, not a claim that every feature ships in 0.3.0. New integrations, cloud disclosure, credentials, paid use, device permissions and production deployment need their own explicit setup/authority. Imports, files, memories and model output are data, not execution permission.

## Stage 2 — quality and inference completion

- Actual device install/lifecycle/permission and Android16 edge-to-edge checks, including Redmi/HyperOS battery restrictions, app intents, picker export/readback, notification delivery, weak-network handling. Owner-supplied OS/hardware is planning context, not test evidence.
- Find a licensed on-device LLM candidate that passes representative English, Assamese, Hindi (Devanagari), Hinglish (Romanized Hindi/English), arithmetic and concise tutoring fixtures. Prior small Qwen candidates failed arithmetic, Assamese quality, or study-answer usefulness; the new language targets are requirements, not verified support. Then implement a licensed Android runtime, measured free-space preflight, user-started verified download/removal, cancellation and strict no-network fallback, and qualify RAM/heat/latency on API36 and the actual phone. Linux inference results alone do not qualify a phone tutor.
- Candidate named for future assessment only: Gemma 3 1B int4 on LiteRT-LM, roughly 584 MB as a preliminary estimate; that exact artifact/size is not pinned. The [LiteRT Community model card](https://huggingface.co/litert-community/Gemma3-1B-IT) currently lists CPU int4 QAT at 529 MB and an NPU int4-weight variant at 689 MB, with benchmarks on Samsung flagships—not this Redmi. Use it only under the [Gemma Terms](https://ai.google.dev/gemma/terms); no Redmi or Assamese quality gate has passed. Qwen3.5 2B/4B Linux probes still fail concise tutoring and/or Assamese gates, so Offline AI remains unavailable.
- Multi-provider profiles and routing by task/capability/cost/latency within configured user budgets; clear tokens/context/cost exposure. No paid auto-routing without approval. Actual model capability gates for images, long context and tools.
- Real local semantic embeddings and semantic past-conversation retrieval, distinct from current keyword search. Embeddings remain local unless remote processing is explicitly chosen. Automatic long-chat summaries may compact retained history, but never silently become approved memory. Relevance/provenance/edit/corrections and uncertainty-aware answers, not invented confidence scores.
- Selectable personalities/response styles, deeper planning/multi-step reasoning, real web retrieval/fact-checking with source citations. No fabricated web results or sources; no execution merely because a plan says so.
- Voice qualification separately for English, Assamese, Hindi and Hinglish: exact installed on-device ASR locale, transcript accuracy, exact offline TTS voice/script and naturalness, code-switch handling for Hinglish, push-to-talk, foreground hands-free, streaming/interruption, adjustable voice/speed/language, summaries, noise handling, automatic language detection and earphones. A language selector entry does not prove device support. Optional wake phrase remains experimental and unimplemented; it does not authorize an always-on microphone. No silently substituted language/network service.

## Stage 3 — Android and multimodal tools

- Owner-requested richer website-like motion, user-started screen sharing, and granular Android permission handling remain future work. Screen sharing would use [MediaProjection](https://developer.android.com/media/grow/media-projection), with Android system consent for each session and required foreground-service handling on Android 14+; this is not background or always-on capture. Android notification access is a user-granted [runtime permission](https://developer.android.com/develop/ui/views/notifications/notification-permission). HyperOS autostart remains an owner-controlled setting ([Xiaomi HyperOS guidance](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1624)). [Accessibility services](https://developer.android.com/guide/topics/ui/accessibility/service) are specialized assistive tools, not general automation; no Accessibility service will be added without a specific assistive use case. None of these items is implemented or qualified in this increment.

- Broader supported installed-app discovery/intents, alarms/calendar/task management, explicitly permitted selected notification access, share text/links, selected-file search, shortcuts, quick tile/widget and floating views where OS/owner permissions allow. No accessibility/overlay/notification blanket access.
- Selected photos/screenshots/diagrams, local OCR/PDF/doc/notes extraction, voice+image interaction, explicitly started camera, provider image generation. Engine must actually support input/output; no text-only “vision” claim, fabricated extraction or silent upload. Extracted text is untrusted data.
- Offline saved study materials/PDF notes, real quizzes/answer keys/explanations, timetable, writing/grammar and recorded progress. User-authored flashcards, spaced repetition and a local multiple-choice practice quiz built only from distinct saved flashcard answers are implemented in the current study screen. Quiz scoring is session-only; it does not update spaced-repetition or claim mastery. No generated study content or mastery estimate is used.
- Coding assistant with reviewable suggestions; future safely isolated server coding playground is separate sandbox work, not arbitrary generated shell on the phone/build computer.
- Living interface: customizable avatar, dynamic wallpaper/accent, compact/expanded/immersive voice views, optional haptics, richer 2D/3D orb states. Listening/thinking/speaking reflect real runtime; battery/performance/accessibility first, reduced motion honored.

## Stage 4 — automations, dashboard and integrations

- Personal dashboard: opt-in real briefings/summaries, calendar/tasks/reminders, customizable cards, genuine recorded activity/productivity statistics, knowledge library/search; optional weather/news/technology sources. No made-up activity and no Wabi briefing schedule is created by this app request.
- Visual block workflow studio: explicit triggers/conditions/schedules/steps/services, previews before enable, execution/failure history, pause/cancel/undo only where truly supported, safe recoverable retries. Example: scheduled study task plus reading selected study plan aloud. Consequential steps need exact approval; uncertain external effects must be reconciled before retry. No promise of universal undo.
- Reviewed API/plugin/integration marketplace (calendar/email/notes/tasks/custom APIs/MCP), per-plugin permissions, scoped authentication and workflow import/export. No arbitrary code, inherited permission, new service account or live deployment by default. Community imports are data until reviewed/enabled.
- Owner-requested connector feasibility (not implemented): [WhatsApp Cloud API](https://developers.facebook.com/docs/whatsapp/cloud-api/overview) is a WhatsApp Business Platform requiring a business portfolio/WABA and a backend webhook endpoint; it is not access to a personal WhatsApp inbox. [Instagram APIs](https://developers.facebook.com/docs/instagram-platform/overview) require a professional Business or Creator account and permissions/login; broader access can require Meta review. [Telegram bots](https://core.telegram.org/bots/faq) receive messages routed to the bot and selected group updates, not a person’s private account inbox. Gmail, Drive and Calendar use separate API-specific, narrow OAuth scopes ([Gmail](https://developers.google.com/workspace/gmail/api/auth/scopes), [Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [Calendar](https://developers.google.com/workspace/calendar/api/auth)). GitHub can use fine-grained permissions restricted to selected repositories ([GitHub token guidance](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)). A public [Notion OAuth connection](https://developers.notion.com/docs/authorization) lets the user select pages and exchanges its authorization code for tokens through the backend. Each other service needs its own API, consent, scope and security review. No credentials or grants were requested or configured.
- Expanded API/model management, executable custom MCP tools/plugins with owner-approval integration, and a user-started model download for offline use remain future work. The Settings MCP manager supports only server registration, optional bearer authentication and read-only tool discovery; this does not implement tool execution. Any model download needs a compatible, licensed candidate, free-space preflight, cancellation/removal and on-device quality, memory and thermal qualification before Offline AI can be enabled.
- Broader privacy/security center: deeper sensitive-data encryption and key-management review; memory review/delete; per-feature microphone/camera permissions; data export and appropriately scoped account deletion; actual usage/API-cost metering. Account deletion cannot erase external-provider copies by assertion. The basic optional device-auth app lock is now in the current increment.
- Security-log intent is recorded. The owner's phrase **“Security log for”** was incomplete; its object/scope must not be invented.

## Stage 5 — optional companion and ecosystem

- Desktop companion continuing authorized conversations/tasks; selective cross-device chat/memory sync with explicit selected data, per-device access and revocation. Desktop stays optional; no computer dependency returns to phone-local functionality. No default sync/upload/sharing.
- Custom reusable skill builder, specialized research/coding/planning multi-agent workflows and knowledge graph linking people/projects/notes/concepts. Children cannot widen authority; skills are not arbitrary executable model code.
- Authenticated/scoped developer API for authorized assistant capabilities, reviewed community workflows/integrations. No public endpoint, unreviewed execution or deployment now.
