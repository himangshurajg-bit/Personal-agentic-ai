# MYRA Ultra Android (private development)

The original project contains the preserved WebView/Chaquopy prototype and a separate native Kotlin/Jetpack Compose app under `native-android/`. The native app is an incremental port, not yet feature-complete. See [`FEATURE_MATRIX.md`](FEATURE_MATRIX.md) for implemented behavior and explicit gaps, and [`ANDROID_ARCHITECTURE.md`](ANDROID_ARCHITECTURE.md) for the broader port plan.

## Build the native Android preview

From `native-android/`, run `./gradlew assembleDebug`. A JDK and Android SDK are required. The development APK is written to `app/build/outputs/apk/debug/app-debug.apk` and is ignored by Git; a successful build alone does not prove installation, runtime correctness, or target-device support.

The source snapshot’s native work includes a Compose shell, locally persisted task list with case-insensitive title search and All/Open/Completed filters, a local expense ledger with monthly totals, a 25-minute focus / 5-minute break countdown, and a date-stamped water log with quick-add/custom milliliter entries, daily totals, and an optional user-set 250–20,000 ml goal with capped daily progress, manual habit check-ins with streaks, and a dated journal stored on-device. These records and timer state use app-private preferences; the water goal is optional and user-set (not a recommendation), is included in plaintext and encrypted backups, and does not schedule hydration reminders; older backups without a target restore with no target set. The timer stores a deadline and can recompute its countdown when the app is reopened, but it does not schedule notifications or run as a background service. The app also has browser handoff for web queries, SAF file selection with a bounded text preview, image preview/camera thumbnail, local preferences, and user-tapped battery/clipboard/vibration actions. For an explicit request to open a supplied HTTP(S) URL, Chat displays the full link for review and opens Android's link handler only after approval; it does not submit forms or confirm the page loaded. This handoff has JVM/build coverage only and is not device-tested. A supplied exact mailto link can open an email composer only after MYRA previews its single recipient, subject, and body for approval; MYRA never sends it, and the user must tap Send. Its parser, request gate, and intent builder have JVM/build coverage only; opening a real composer is not device-tested. For an explicit WhatsApp message request with exactly one full international number, Chat shows the exact recipient and message for review, then can open WhatsApp with the message prefilled; MYRA never sends it, searches contacts, or claims delivery, and the user must tap Send in WhatsApp. This handoff has JVM/build coverage only and has not been tested on a device. In Chat, Gemini may prepare an immediate local Android notification only after the latest message explicitly asks for one; MYRA shows the exact bounded title and text for review, and Android 13+ permission is requested only after approval. This does not schedule a reminder. Gemini can also offer an explicitly requested, exact 0–255 brightness change for native approval; it affects only MYRA’s current app window and restores the previous window value when Chat closes or MYRA backgrounds, never changing system brightness. This chat handoff has JVM/build checks only and is not device-tested. The Tools clipboard preview reads only the first plain-text item after a tap, stays local and is not sent to Gemini, is capped at 4,000 characters, and clears when MYRA backgrounds or Tools is left. Tools can also open Android’s contact picker and read only the single phone contact the user selects; it does not enumerate or save the address book, request broad Contacts permission, or send contact details to Gemini. The Tools screen’s one-shot approximate location lookup asks for coarse permission only after the user taps, displays the fix transiently on-device, and opens Maps only after a second explicit tap; that Tools flow does not persist or send location to Gemini. Separately, Chat can request one rounded current-location fix only after a direct latest-message request; Android coarse permission is requested then, and the exact rounded coordinates and reported accuracy appear in a native review before any transfer to Google Gemini. Declining or lacking a fix shares nothing; there is no background tracking or location persistence. Intent, empty-argument and rounding tests plus the build cover this code, but permission/provider/freshness/review and live Gemini behavior still need device testing. In Chat, Gemini may request `set_timer` only for one direct latest-message request that states one exact duration in seconds, minutes, or hours (up to 24 hours). MYRA validates the duration against that message, previews the request for native approval, then opens Android Clock with its review UI enabled; the user must confirm it there, and MYRA cannot verify that the timer started. The timer handoff has JVM/build coverage only; native review, Android Clock behavior, Android 16/Redmi compatibility, and live Gemini have not been runtime-tested. Native chat also has bounded on-device history, user-invoked Android speech recognition and text-to-speech, and a Gemini text-request path with an Android-Keystore-encrypted API key. Live voice now has a saved “Allow barge-in during Live voice” switch: off by default, it pauses microphone upload while MYRA is expected to speak; when enabled, the mic stays active so you can interrupt, and headphones are recommended to reduce echo. The foreground lifecycle now closes the latest bound session instead of a stale value captured when the observer was first composed; late closure from an old session cannot clear its successor. Barge-in, echo behavior and Activity lifecycle effects still need device testing. The Files page can send a selected JPEG, PNG, or WebP image up to 4 MiB to Google Gemini only after the user taps Analyze; an on-screen disclosure explains this transfer. The request builder rejects mismatched image signatures and size/MIME violations. JVM tests also cover expense validation/serialization/month totals, timer countdown arithmetic, water amount/date validation and daily totals, habit check-ins/streak arithmetic, and journal validation/serialization/sorting. Gemini network and audio behavior remain untested on a device. No API keys are bundled.

A native Compose smoke test is present for app launch, navigation among Home/Chat/Tasks/Tools/Files/Settings, and local task entry. The configured GitHub Actions API 36 run (`39937493614`) timed out before the emulator booted because the Ubuntu runner had no usable `/dev/kvm`; the instrumentation test never ran. The local host also cannot boot API 36 under software emulation, so there is no app install/runtime result or Gemini network result. A hardware-accelerated hosted route would require a separate runner decision; no new retry is authorized here.

The upstream project has conflicting licensing signals and contains hardcoded Firebase key strings in desktop modules. Those modules are excluded from this Android work. That statement described the original development repository before redistribution was authorized. The owner confirmed authority for this public source transfer on 28 October 2026; see the target repository’s `docs/MYRA_TRANSFER.md`.


### Current local Android features

The native Tools screen includes a local expense ledger, a foreground focus/break timer, a manual water-intake log with an optional user-set daily target (no hydration reminders), a habit tracker with daily check-ins and current streaks, and a dated local journal. These records stay in app-private storage; the habit tracker does not schedule reminders, sync, or provide health advice. Other MYRA desktop integrations and workflows remain unported; see `FEATURE_MATRIX.md` for the implementation boundary and runtime-test limitations.


In Chat, Gemini may offer to copy text only when you explicitly ask to copy that exact text from your latest message. MYRA shows the complete text for approval before replacing Android's clipboard; other apps may be able to read clipboard contents. This reviewed clipboard action has JVM/build coverage only and has not been runtime-tested on a device. Gemini can also request a persistent reply-language change only when your latest message explicitly asks for one supported language by name; MYRA shows the exact choice for approval and saves it only after you approve. It does not rewrite existing chat history. This setting handoff has JVM/build coverage only and has not been runtime-tested on a device. From Chat, Gemini can also offer to save a preferred name only when the latest message explicitly states that name; MYRA previews it for approval, then stores it in local settings and uses the saved value as a name-only personalization hint in later requests. This change has JVM/build coverage only and has not been runtime-tested on a device.

A separate Chat action can read only the first plain-text clipboard item after a direct explicit latest-message request. MYRA displays the exact excerpt (up to 4,000 characters) for native approval before sharing it once with Google Gemini; it does not read automatically or monitor changes. Clipboard contents are untrusted data, not instructions, and the resulting chat is saved on this device as usual. The Tools-screen clipboard preview remains local-only. Intent, argument, clipping and response-size tests/build pass; Android clipboard access, review behavior and live Gemini transfer have not been device-tested.


Gemini can also request opening one explicitly named app from a limited, prototype-backed list: Calculator, Camera, Chrome, Clock, Files, Gmail, Maps, Settings, Spotify, YouTube, WhatsApp, WhatsApp Business, Instagram, YouTube Music, Google Photos, Messages, Telegram, Google Calendar, Google Drive, Play Store, Facebook, or LinkedIn. MYRA requires the latest message to explicitly name one app, shows a native review, then launches only that app after approval; it does not enumerate apps or open arbitrary package names. This expansion has JVM validation and build coverage only; actual package availability and review/launch behavior are not device-tested. A direct request to search one exact phrase on YouTube or Spotify can also open a reviewed search URI after MYRA previews the service and query; it never starts playback, and the user selects the result. Validation, exact latest-message gating and encoded search URIs have JVM/build coverage only; the native review and app handoff are not device-tested.

For a direct request to set a one-off alarm at one exact 24-hour time such as 07:30, Gemini can ask MYRA to preview the request in a native review. After approval, MYRA opens Android Clock with its review UI; you still need to confirm the alarm there, and MYRA cannot verify that Clock saved it. Ambiguous, future, repeating, timer and reminder requests are excluded. JVM tests/build cover validation and latest-message matching; the native dialog and Clock handoff are not device-tested.

The native Chat tool `show_toast` is available only for a direct, explicit latest-message request containing the exact toast text. MYRA shows a native review first, then displays the approved text briefly inside the app; it is not a notification and is not stored. Text is capped at 120 printable characters. JVM validation is covered; Android dialog/display behavior still needs device testing.

In Chat, Gemini may request `share_text` only when the latest message explicitly asks to share or forward the exact text it supplies. MYRA caps it at 4,000 printable characters, previews it for native approval, and then opens Android’s Sharesheet; MYRA does not pick a destination or send the text, and the user must choose and confirm in the receiving app. Policy/intent gating and request bounds have JVM/build coverage only; the review and target-app handoff have not been tested on-device.


For a direct request for directions to one exact place or address written in the latest message, Gemini can request `navigate_to`. MYRA validates and previews the destination for native approval, then opens an encoded Android Maps search; it does not start or verify navigation, and the user chooses what to do in Maps. Request validation, exact-place intent gating, and URI construction have JVM/build coverage only; the native dialog and map-app handoff are not device-tested.


In Chat, the prototype-backed `download_file` Gemini action is available only when the latest message directly requests downloading and includes the exact HTTP(S) URL. MYRA previews the full URL and sanitized filename for native approval, then starts Android Download Manager; Android 8.0–9 asks for legacy storage permission only after approval. The transfer may use network data, and MYRA does not claim that a started download completed. URL policy, exact-intent gating and request validation have JVM/build coverage only; native review, permission flow, and network behavior have not been device-tested.


In Chat, Gemini can request `take_photo` only when your latest message directly asks for a photo or picture. After native approval, MYRA opens Android's default camera and shows only its returned thumbnail temporarily in Chat; it does not save the image, send it to Gemini, or select a camera lens. Camera apps may return no thumbnail, in which case MYRA reports that without claiming a photo was captured. The existing Files camera flow remains separate and can save a full-resolution image after a user starts it. Request validation and intent matching have JVM/build coverage only; the camera UI and result are not device-tested.


Chat also supports prototype-backed `find_contact` for one explicitly named person. MYRA first asks before opening Android's system contact picker; after you select one contact with a phone number, a separate review shows the exact name and number before any one-time sharing with Gemini. It reads only the selected picker URI, never scans or saves the address book, requests no broad Contacts permission, and treats contact fields as untrusted data rather than instructions. Policy tests/build cover request validation and intent gating, but picker behavior, both native reviews, device compatibility, and live Gemini transfer have not been tested on-device. The existing Tools contact picker remains local-only.


Live voice exposes three narrow tools: a direct battery-status question can read the current battery percentage/charging state; a direct spoken volume request must name one supported stream and one exact percentage; and a direct flashlight request must name one on/off direction. Volume and flashlight actions show the existing native approval before changing anything; turning on the flashlight requests Camera permission only after approval and reports success only after Android callback confirmation. Microphone uplink pauses while Gemini speech is expected to play, with a 250 ms tail to reduce echo unless the saved barge-in toggle is enabled; headphones are recommended when using barge-in. At most one device tool call is handled per spoken turn, and malformed, indirect, negated or unsupported requests fail closed. For an unexpected disconnect or Gemini `GoAway`, MYRA can make at most two bounded reconnect attempts with a fresh short-lived token and the latest eligible server resumption handle. The opaque handle stays in memory only, is never logged or persisted, is updated only from a `resumable=true` update with a valid non-empty handle, and is cleared when Live is stopped; after a detected disconnect it is discarded no later than two hours later. `GoAway.timeLeft` is used to begin reconnect shortly before the server closes the session. Focused JVM tests cover the handle policy, expiry, backoff and protocol framing, alongside foreground session binding and stale-close handling; real session resumption, Live service behavior, approval, permissions, audio timing and Activity lifecycle behavior remain unverified on-device.


The Gemini SSE reader now limits each network line to 1,000,006 characters while reading incrementally, before creating a full line string; the parser separately enforces its 1,000,000-character event cap, including separators between `data:` lines. This closes an unbounded `readLine()` allocation path for malformed or unexpectedly large stream responses. JVM tests cover line endings and size boundaries; live network behavior remains untested.
