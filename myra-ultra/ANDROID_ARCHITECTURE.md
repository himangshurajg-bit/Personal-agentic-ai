# Android architecture decision and staged port plan

## Decision

Use a native Kotlin + Jetpack Compose application as the intended full Android product. The original WebView + embedded Python APK is a clearly labeled prototype/bootstrap only: it proves the copied Python package can be bundled and its existing web UI can be hosted, but it does not establish feature parity, native Android integration, or production readiness. The source snapshot preserves it under `prototype/`; do not replace it destructively.

Use Chaquopy selectively for isolated portable MYRA Python logic (for example prompt/response formatting or compatible provider/client modules after dependency checks). Do not embed the desktop PyQt UI, duplicate desktop UI inside a WebView as the final app, or expose Termux shell commands as Android APIs. Rust is not justified as an app framework; consider it only if profiling later proves a portable performance-critical component.


## Source UI parity checkpoint

The Termux chat UI in `prototype/app/src/main/python/myra_termux/ui_html.py` defines eight quick prompts in `Q` and renders them as horizontally scrolling chips. Native Chat reproduces their source order/text and feeds the same guarded Gemini route. The source portrait/orb hero is mapped to `SourceVoiceHero`: it uses the exact bundled `assets/myra.jpg`, source `clamp(250px,42vh,380px)` sizing, the ≤560px viewport 120px hero override and 158px compact Chat hero, 84px orb/0.78 chatting scale, source crop position, overlay gradient and the idle/active radial color stops. Idle/listening/thinking/speaking map to crimson/mint/ember/sky, source Hindi status copy, source SVG microphone outline/stroke widths, an 8dp-outset pulse ring and source pulse/breath timing. `GeminiLiveSession` maps returned audio chunks to speaking until the queued 24 kHz mono PCM duration reaches the source UI's 20ms tail, then returns to listening; interruption clears the queue, while tool calls and token/connect/reconnect stages map to thinking and source-matched Hindi copy. Home orb taps navigate to Chat rather than pretending to start microphone capture; in Chat the orb shares the existing permission-gated Live session path. State, audio-queue and layout tests pin these values and transitions. Android's `ValueAnimator.areAnimatorsEnabled()` gates repeating animations when the system animator setting reports them disabled; it does not claim to reproduce every browser `prefers-reduced-motion` preference. The Android Preferences destination now maps the source settings sheet structure responsively: 560dp max width, 88% available-height cap, bottom anchoring and 28dp upper corners, fixed title/footer around a scrollable body, 18dp field gaps, 48dp minimum actions, and a language list capped to 30% available height. Its language finder searches code/name/native text, places Auto — Hinglish first and caps the initial result set at 80; name input is limited to 30 characters. Name/language/barge-in values stage until Save; Close discards them. Headphones-mode defaults off and persists in Android settings; the Gemini model selector and encrypted key-management controls are Android extensions not in the prototype web sheet. Auto is the source default and emits no forced language instruction; Android uses the device default TTS locale as a documented approximation rather than upstream adaptive browser speech. Chat clearing is confirmation-gated and clears this app’s persisted local transcript; upstream `/api/reset` clears only `SESSION.history`. API keys remain encrypted on device and are not validated against the upstream settings endpoint. The source modal layering is now partly mapped: Home/Chat settings open a full-window Compose dialog over the navigation scaffold, with the source `#000a` backdrop dim amount and the existing 560dp/88%-height bottom sheet; the explicit bottom-navigation Settings destination remains available. The orb now scales to 0.95 while pressed using the source 200ms transform transition and default CSS `ease` curve. Hero height and portrait object-position animate on source-matched 450ms CSS Bézier curves, and hero text explicitly uses Android's system sans family with source size/weight/letter spacing. The source wrapper system-bar color (`#101116`) and dark-status-icons-disabled flag now map through `SourceChromePresentation`; remaining differences include platform font metrics and image/crop rendering, exact backdrop/nav-bar insets and visual interpolation, source server-side key validation and adaptive web speech, and AudioTrack's device-dependent output latency; native runtime and visual checks remain outstanding. This is a source-backed native adaptation, not pixel-exact proof. Do not use a WebView duplicate as a substitute for the native Android product.

## Proposed feature-to-module mapping

| Original MYRA capability | Native Android module / approach | Port constraints and acceptance evidence |
|---|---|---|
| Home/dashboard | `feature:home` Compose screens; shared state in `core:model` | Rebuild from user-facing requirements; desktop widgets do not transfer directly. |
| Chat, provider selection, tools | `feature:chat`, `core:ai`, `core:data`; Kotlin coroutines/OkHttp or compatible Python core through Chaquopy | Reuse protocol/business logic where dependency-compatible; secure user API keys with Android Keystore-backed storage. Test streaming, errors, offline/retry and tool consent. |
| Live voice, speech input/output, multilingual modes | `feature:voice`, Android audio APIs and foreground service; add `RECORD_AUDIO` only at point of use | Rework the desktop/Termux voice transport and audio pipeline; verify lifecycle, Bluetooth/headphones, interruption, permissions, languages and round-trip tests on real Android devices. |
| Android device tools (battery, torch, vibration, notifications, volume/brightness, clipboard, apps, URL) | `feature:device`, narrow interfaces in `core:platform`, native Android APIs / intents | Some actions are restricted by Android version/policy or require user-visible confirmation; implement only supported APIs and test permission denial/revocation. Do not port shell commands verbatim. |
| SMS, phone calls, contacts | `feature:communications` with Android intents and `ContactsContract` picker; prefer `ACTION_SENDTO` / `ACTION_DIAL` | Avoid silent sending/calling or broad address-book access; owner must review messages/calls. SMS/Call Log permissions are restricted for Google Play distribution and may be unavailable to ordinary apps. |
| Camera, photos and media | `feature:camera` with CameraX; `feature:media` with Media3 and Android Photo Picker | Requires camera/audio permissions and Android lifecycle handling; validate capture/playback, formats, storage, orientation and privacy. |
| Screen sharing / screen capture | `feature:screen-share` using `MediaProjection` foreground service | Android requires per-session system consent; cannot silently capture or keep a projection after consent/session ends. Add service type/foreground notification and Android 14+ behavior tests. |
| Files & documents | `feature:files` using Storage Access Framework / Photo Picker; document parsing in `core:documents` | No broad filesystem access; document types and large-file processing need bounded, tested parsers. Desktop paths/Windows APIs are not portable. |
| Automation, reminders, alarms, timers, quick tools | `feature:automation`, `feature:tools`, WorkManager for deferrable tasks; AlarmManager only for justified user-requested exact alarms | Android background limits prevent arbitrary always-on desktop automation; exact alarms can require special access and cannot be promised without approval/grant. |
| Web & search | `feature:search`, provider interface in `core:network` | Preserve provider limits, consent and network error states; no browser login bypass. |
| Website Studio / MYRA Coder / WebForge | `feature:studio`, isolated editor/preview and file export | Major product surface requiring separate design, safe code execution/isolation and extensive validation; server/deploy actions need explicit user intent. |
| System monitor | `feature:system` using supported `BatteryManager`, `StorageStats` and network APIs | Android does not expose all desktop metrics; show unavailable metrics honestly and respect privacy/background limits. |
| Settings, About, language/name | `feature:settings`, Preferences DataStore, Android Keystore for secrets | Migrate settings with validation; never copy plaintext API-key storage into native production settings. |

## Gradle/module outline

- `:app` — minimal Android entry/activity, dependency injection, navigation and app theme.
- `:core:model`, `:core:data`, `:core:ai`, `:core:platform`, `:core:security` — shared models, repositories, provider contracts, Android adapters and secret handling.
- `:feature:home`, `:feature:chat`, `:feature:voice`, `:feature:device`, `:feature:files`, `:feature:media`, `:feature:automation`, `:feature:search`, `:feature:studio`, `:feature:system`, `:feature:settings` — user-facing Compose feature boundaries.
- Optional `:core:python` — only if each Python dependency has Android-compatible wheels/native binaries for target ABIs and Chaquopy interop is covered by tests. Existing termux CLI/UI, shell wrappers, desktop imports and platform-specific modules must not be pulled into the app by default.

Likely libraries: AndroidX Compose BOM, Activity Compose, Lifecycle, Navigation Compose, DataStore, Room (only where local relational data is needed), WorkManager, CameraX and Media3. Add libraries incrementally after checking current stable versions and min/target SDK compatibility; no dependency is required merely because a plan names it.

## Work sequence and gates

1. Freeze and retain the current WebView/Chaquopy prototype and its verified debug APK; create the native project alongside it, never overwrite it.
2. Build an exhaustive source capability inventory and mark each item Android equivalent / adapted / unsupported, including quick tools and all Termux actions.
3. Inspect desktop imports and package metadata per feature; separate portable Python business logic from PyQt, Windows, shell and native-library dependencies. Check all Android ABI dependency support before selecting reuse.
4. Create native Kotlin/Compose foundation, app navigation, state, test harness, secure settings and design primitives. Build a signed-debug APK and verify install/launch on emulator.
5. Port feature-by-feature with permission UX and unit/UI/instrumentation coverage; no feature is “ported” until behavior is tested. Add device-specific integrations only through supported Android APIs and user-visible consent.
6. Run Android emulator/API matrix and then real-device checks on Redmi 24090RA29I; build a current gap report. Do not claim device compatibility from compilation/emulator checks.
7. Historical original-repository policy required the GitHub repository to remain private until public redistribution rights were established. On 28 October 2026, the owner confirmed that they control the relevant rights and authorized this public source transfer. The target repository’s transfer note records that authorization and the remaining limitations. A secret scan was performed on the exact included source snapshot; the desktop tree and its Firebase-key-bearing files remain excluded.

## Current risks / blockers

- Upstream code is split between PyQt desktop modules and a Termux package; UI/OS integrations require a substantial native rewrite, not a framework toggle.
- The current prototype uses a local Python HTTP server plus WebView and stores provider configuration in its inherited app-private JSON flow. That is acceptable only as a development prototype; production requires a native security/storage review and explicit secret-handling redesign.
- Python package metadata labels `myra-termux` Proprietary while the repository root has MIT. The original private-reuse statement did not establish public redistribution authority at the time. The owner subsequently confirmed on 28 October 2026 that they control the relevant rights and authorized this public source transfer; see the target repository’s `docs/MYRA_TRANSFER.md`.
- Some original capabilities cannot be replicated exactly on Android because Android restricts background work, silent SMS/calls, filesystem access, screen capture, exact alarms and access to desktop-level system metrics. Each needs a safe Android equivalent or a documented unsupported gap.
- No Android emulator/ADB or Redmi hardware is available in this build environment. The existing APK was compiled and signature-verified only; installation, runtime behavior, audio, permissions and target-device compatibility remain unverified.
